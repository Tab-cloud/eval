# 前端主题与移动端约束

本文件是 `eval_web` 的强制设计约束。新增页面和组件必须同时满足 Dark、Light 与移动端三种状态，不能把浅色模式或移动端作为完成后的补丁。

## 主题模式

1. 必须支持 `dark` 与 `light`，首次访问跟随 `prefers-color-scheme`，用户手动选择后写入 `localStorage` 的 `luban-theme`。
2. 主题状态只写在 `<html data-theme>`，组件不得维护互相独立的主题状态。
3. 设备级主题偏好属于本地 UI 设置，可以使用浏览器存储；用户、权限和业务数据禁止使用浏览器存储作为真实来源。
4. 新颜色必须先定义语义变量，再由两个主题分别赋值。禁止在业务组件中继续增加只适用于深色背景的硬编码颜色。
5. 两个主题都必须保证正文、次级文字、边框、焦点环和状态颜色可辨认；重要正文目标至少满足 WCAG AA 对比度。
6. 页面加载前执行内联主题初始化，避免从默认主题闪烁到用户主题。
7. 主题切换控件使用 SVG 图标并提供 `aria-label`，禁止使用 Emoji。

## 响应式断点

- `> 1100px`：完整侧边栏，多列指标与双栏分析区。
- `761–1100px`：紧凑侧边栏，两列指标；核心图表保留。
- `≤ 760px`：底部导航、单列内容、横向可滚动的完整模块入口。
- `≤ 470px`：单列指标、纵向主操作、压缩登录表单和顶部操作区。

## 移动端交互

1. 任何一级模块在移动端都必须可达，禁止仅用 `display: none` 隐藏后不提供替代入口。
2. 触控目标最小 `44 × 44px`；底部导航需要支持安全区 `env(safe-area-inset-bottom)`。
3. 页面不得产生整体横向滚动。宽表格按优先级隐藏次要列，必要时改为卡片列表或局部横向滚动。
4. 弹窗最大高度基于 `100dvh`，内容超出时弹窗内部滚动；不得让确认按钮落到不可触达区域。
5. 输入框使用适当的 `inputMode` 和 `autocomplete`；移动端聚焦后不得因字号过小触发非预期缩放。
6. Hover 只能增强体验，核心功能必须支持触摸、键盘和屏幕阅读器。

## 动效与性能

1. 动效用于状态变化、层级和空间关系，常规持续时间控制在 `160–320ms`。
2. 必须支持 `prefers-reduced-motion: reduce`，禁用旋转、漂浮和大幅位移动效。
3. 优先使用 `transform` 与 `opacity`，避免触发布局抖动；移动端减少大面积模糊和多层阴影。
4. 图标统一使用项目 SVG Icon 组件或经过审核的图标库，不使用 Emoji、文本图标或来源不明的图片。

## 验收视口

每个正式页面至少检查：`1440×900`、`1024×768`、`390×844`、`360×800`。同时覆盖深色、浅色、键盘导航、减少动效和长中文内容。
